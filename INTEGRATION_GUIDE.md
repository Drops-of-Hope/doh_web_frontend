# Blood Demand Forecast API — Integration Guide

## What this is
A Python/Flask API (`api_server.py`) that serves blood demand predictions
from 3 trained XGBoost models. This doc tells you how to run it and how
to call it from the app.

## ⚠️ Data status (read before wiring anything to production)
The 3 models are currently trained on **placeholder/estimated data**
(`RCC_Issues_est`, `Blood_Requests_est`, `Total_Component_Issues_est` in
`training_data.csv`), not real reported figures — the source reports only
had true monthly granularity for donation collection, not for
requests/issues. The API and app integration below are fully functional,
but the numbers returned are **demo values**, not production-accurate,
until `raw_monthly_demand.csv` is replaced with real monthly data and the
models are retrained (`python3 train_model.py`). Do not present these
numbers to real users as forecasts without doing that swap first.

## Files needed to run the server
Put these in the same folder:
- `api_server.py` — the Flask app
- `model_requests.json`, `model_rcc_issues.json`, `model_total_issues.json` — trained models
- `metrics.json` — per-model error stats + feature importance (generated by `train_model.py`)
- `training_data.csv` — historical data the API uses to build features and chain forecasts

## Running it
```bash
pip install flask pandas xgboost
python3 api_server.py
```
Runs at `http://localhost:5005`. For real deployment, put this behind a
production WSGI server (gunicorn, uvicorn+asgi wrapper, etc.) on a host
like Render, Railway, Fly.io, or an internal server — Flask's built-in
server (what you get from `python3 api_server.py`) is dev-only.

## Endpoints

### `GET /predict?year=YYYY&month=MonthName`
One month, all 3 targets at once.

Example: `GET /predict?year=2025&month=January`

```json
{
  "year": 2025,
  "month": "January",
  "predictions": {
    "Blood_Requests_est": {
      "predicted": 44852,
      "confidence_range": [39885, 49820],
      "same_month_last_year": 42541,
      "change_pct_vs_last_year": 5.4,
      "trend_vs_prev_month": "up",
      "risk": "normal"
    },
    "RCC_Issues_est": { "...same shape...": "..." },
    "Total_Component_Issues_est": { "...same shape...": "..." }
  }
}
```

Field meanings:
| Field | Meaning |
|---|---|
| `predicted` | The model's point prediction |
| `confidence_range` | `[predicted - typical_error, predicted + typical_error]` — show as a range, not a single hard number |
| `same_month_last_year` | Actual value from the same month, previous year |
| `change_pct_vs_last_year` | % change vs a year ago |
| `trend_vs_prev_month` | `"up"` / `"down"` / `"flat"` vs the previous month |
| `risk` | `"high"` if predicted demand is notably above the recent 6-month average, `"low"` if notably below, else `"normal"` |

Only works for the month immediately following known history (or a
previously-forecasted month within the same server session, see
`/forecast`). Returns `400` with an `"error"` message if there isn't
enough history yet.

### `GET /forecast?start_year=YYYY&start_month=MonthName&months=N`
Same fields as `/predict`, but for N consecutive months, chained forward
(each month's prediction feeds the next month's "previous month" feature).
Use this for a chart instead of a single number.

Example: `GET /forecast?start_year=2025&start_month=January&months=6`

```json
{
  "months_forecast": 6,
  "forecast": {
    "Blood_Requests_est": [ { "month": "January", "predicted": 44852, "...": "..." }, "... 5 more months ..." ],
    "RCC_Issues_est": [ "... 6 months ..." ],
    "Total_Component_Issues_est": [ "... 6 months ..." ]
  }
}
```

### `GET /why?target=Blood_Requests_est`
Feature importance for one model — use for a "why this forecast?"
tooltip/expander. `target` must be one of `Blood_Requests_est`,
`RCC_Issues_est`, `Total_Component_Issues_est`.

```json
{
  "target": "Blood_Requests_est",
  "model_mae": 4967.3,
  "model_r2": -1.25,
  "feature_importance": [
    { "feature": "PrevMonthDemand", "importance": 0.2141 },
    { "feature": "MonthSin", "importance": 0.2024 },
    "..."
  ]
}
```

## UI suggestions (map directly to fields above)
- **Headline number**: `predicted`, formatted with commas.
- **Range chip under it**: "Expected range: {confidence_range[0]}–{confidence_range[1]}" instead of a falsely-precise single number.
- **Trend arrow**: ↑/↓/→ from `trend_vs_prev_month`.
- **YoY badge**: "+5.4% vs Jan 2024" from `change_pct_vs_last_year`, colored green/red.
- **Risk badge**: colored pill from `risk` (red=high, yellow=normal, green=low) — good for a dashboard at-a-glance view.
- **Chart**: feed the `/forecast` array straight into a line/bar chart component (each item has `month` + `predicted`).
- **"Why this forecast?" expander**: call `/why` on demand, list top 3 features from `feature_importance`.

## Example fetch (JavaScript / any web frontend)
```javascript
async function getForecast(startYear, startMonth, months = 6) {
  const res = await fetch(
    `http://localhost:5000/forecast?start_year=${startYear}&start_month=${startMonth}&months=${months}`
  );
  if (!res.ok) throw new Error((await res.json()).error);
  return res.json();
}

// usage
const data = await getForecast(2025, "January", 6);
const requestsChartData = data.forecast.Blood_Requests_est.map(m => ({
  month: m.month,
  value: m.predicted,
  low: m.confidence_range[0],
  high: m.confidence_range[1],
}));
```

## Retraining with real data (once available)
1. Replace the estimated columns in `raw_monthly_demand.csv` with real
   monthly `RCC Issues` / `Blood Requests` / `Total Component Issues`
   figures (see `generate_raw_dataset.py` for the expected column names).
2. Run `python3 build_training_data.py` → regenerates `training_data.csv`.
3. Run `python3 train_model.py` → regenerates the 3 `model_*.json` files
   and `metrics.json`.
4. Restart `api_server.py`. No other code changes needed — the API
   contract (endpoints/fields above) stays identical.
